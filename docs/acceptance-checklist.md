# 一期验收清单与记录模板（TOB-336 验收标准 1–10）

父 PRD 验收标准的逐条验证规程。原则：能脚本化的项脚本化（`scripts/e2e-acceptance.sh`），必须人工/真实环境完成的项给出步骤与记录字段，**验证人如实填写，不虚报**。

## 快速开始

```bash
# 本地全链路实跑（自动拉起面板 + agent + 假 napcat，覆盖 1/3/4/5/7/9）
scripts/build.sh && scripts/e2e-acceptance.sh

# 用户环境（对已部署面板跑，覆盖 1/3/4/5/7/9 的真实环境版本）
# 前置：已有一台登记设备并拿到 agent token（设备 ID + token 在创建时显示一次）
PANEL_BASE=https://<tunnel域名> ADMIN_PASS=<面板密码> \
  AGENT_TOKEN=<设备token> DEVICE_ID=<设备ID> \
  FAKE_NAPCAT=0 NAPCAT_URL=http://<napcat地址>:3000 NAPCAT_TOKEN=<napcat token> \
  NAPCAT_TARGET_TYPE=private NAPCAT_TARGET_ID=<QQ号> \
  scripts/e2e-acceptance.sh
```

脚本产出 `acceptance-record.jsonl`（逐条结论）与 napcat 收件记录（JSONL），即为验收证据。

## 逐条规程与记录模板

### 1. 外网经 Tunnel 域名访问：未登录被拒；登录后功能正常

- 脚本部分：`e2e-acceptance.sh` 验收 1（对 `PANEL_BASE` 做未登录 401/登录 200 断言）
- 人工部分（仅用户环境）：浏览器打开 `https://<tunnel域名>`，未登录应跳登录页；登录后各页正常
- 记录：`访问域名 / 未登录行为 / 登录账号 / 各页面截图 / 执行人 / 日期`

### 2. k3s 删除 Pod 重建，数据不丢（PVC 生效）

- 仅用户环境（k3s 集群）：
  1. 按 `docs/deploy-k3s.md` 部署，登记设备并产生若干指标点
  2. `kubectl delete pod -n <namespace> <panel-pod>`，等 Pod 重建就绪
  3. 重新登录：设备台账、指标曲线、告警配置与删除前一致
- 记录：`删除的 Pod 名 / 重建耗时 / 删除前后数据对比截图 / 执行人 / 日期`

### 3. 新设备安装 agent，5 分钟内在线并出指标曲线

- 脚本部分：`e2e-acceptance.sh` 验收 3（在线 + 30s 周期指标断言）
- 记录：`设备名 / agent 启动到在线耗时 / 首个指标点延迟 / 执行人 / 日期`

### 4. 停 agent，60s 内离线并 QQ 收到含设备名的离线告警

- 脚本部分：`e2e-acceptance.sh` 验收 4（离线判定 + napcat 侧收到的消息内容断言）
- 用户环境注意：脚本以假 napcat（或真实 napcat HTTP）为准；「QQ 客户端真的弹消息」需人工确认
- 记录：`停 agent 时刻 / 离线判定耗时 / QQ 收到内容截图 / 执行人 / 日期`

### 5. CPU 超阈值持续 1 分钟，QQ 收到含设备名/指标/当前值的告警

- 脚本部分：`e2e-acceptance.sh` 验收 5（本地模式自动施压；远程模式自动按观测值设阈值，仍不触发则记 SKIP 并提示在目标机施压）
- 记录：`阈值 / 触发耗时 / QQ 收到内容截图 / 执行人 / 日期`

### 6. 面板打开 Web 终端执行命令成功，操作留痕可查

- 自动化部分：`e2e/tests/terminal.spec.ts`（假 agent 全链路）；本环境实跑另以真 agent PTY 驱动验证（见验收记录）
- 人工步骤（用户环境）：「Web 终端」页选在线设备 → 打开终端 → 执行 `echo ok` 与任一实际命令 → 「终端留痕」页查会话与输入/输出留档
- 记录：`设备名 / 执行的命令 / 终端截图 / 留痕页截图 / 执行人 / 日期`

### 7. 日志页选设备+服务可见最近日志，关键字/级别过滤正确

- 脚本部分：`e2e-acceptance.sh` 验收 7（服务清单 + 尾部拉取断言；目标机需有 systemd/docker 日志源）
- 人工步骤：日志页选设备与服务 → 尾部 N 行可见 → 关键字过滤与级别过滤结果正确
- 记录：`设备/服务 / 过滤关键字与结果截图 / 执行人 / 日期`

### 8. 外网服务器 agent 接入，行为与内网一致

- 仅用户环境：在一台有公网的服务器上安装 agent（`artifacts/agent/linux-<arch>/DevicePanel.Agent`，出站 WSS 回连，无需开入站端口），跑一遍 3/4/6/7 的步骤
- 记录：`服务器位置与网络 / 在线与指标 / 终端 / 日志 各项截图 / 执行人 / 日期`

### 9. napcat 断连期间告警入队，恢复后自动补发、无丢失

- 脚本部分：`e2e-acceptance.sh` 验收 9（断连入队 → 恢复补发 → 队列清空 → napcat 侧收到）
- 用户环境：停掉真实 napcat 容器/进程制造断连，恢复后核对 QQ 实收条数与队列记录一致
- 记录：`断连时段 / 入队条数 / 补发条数 / QQ 实收截图 / 执行人 / 日期`

### 10. 中文界面，响应式布局手机可正常查看

- 自动化部分：`e2e/tests/*.spec.ts` 全站中文断言 + 375px 视口横向溢出断言（登录/设备/指标/终端/日志/告警）
- 人工步骤：手机浏览器打开面板，逐页查看无横向滚动、控件可用
- 记录：`手机型号/浏览器 / 各页截图 / 执行人 / 日期`
